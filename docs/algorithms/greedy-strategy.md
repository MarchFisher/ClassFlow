# ClassFlow 排课算法策略：贪心（Greedy）

> 版本：v1.1 · 日期：2026-08-27
> 关联：docs/需求分析.md（约束与策略源头）、docs/architecture.md（架构）、docs/algorithms/simulated-annealing.md（两阶段策略的另一半）

---

## 1. 概述

贪心算法是排课核心的**构造阶段**算法：以课程为单位，按"约束紧的先排"的顺序，一遍扫描为每个课程生成时间模式并分配教室，**不做回退**。

- **优点**：快、稳定、实现简单；
- **缺点**：排定后不再调整，软约束（离散度、教室利用率）只能靠排序顺序"碰运气"，可能得到局部次优解。

因此贪心既可以作为独立策略使用，也可以作为**模拟退火的初始解生成器**（见 [simulated-annealing.md](simulated-annealing.md)）。

---

## 2. 核心思想

"**先难后易**"：约束越紧的课程越先排。每周课次越多、单次课越长的课程越难排，先排它们、给它们留出最优的时间与教室；排完难的之后，简单的课程找空档就容易得多。

---

## 3. 排课流程

**输入**：课程/教学班（每周课次、单次学时、教师、人数）、教室（容量/类型）、作息表（节次）。

1. **课程排序**：按「每周课次 ↓、单次学时 ↓、教师 ID ↑」排序。
2. **生成时间模式**：按理想间隔 `(5 − N) / (N − 1)` 生成该课程每周 N 次课的时间槽；找不到空闲时间时逐步放宽间隔（3 → 2 → 1 天）。
3. **教学班入组**：同一课程的所有教学班放入同一时间模式，靠教室区分；同时刻空闲教室不足时，按 `classId` 拆成若干组，每组沿用同一套模式。
4. **分配教室**：在满足容量与教室类型（H4/H5）的空闲教室中，选「容量 ≥ 人数且最小」的 best-fit。
5. **校验**：全部硬约束由 `ConflictTable`（`canPlace` / `place`）保证。

---

## 4. 硬约束

| 编号 | 约束 |
|------|------|
| H1 | 同一时间同一教师不能安排两个教学班 |
| H2 | 同一时间同一教室不能安排两个教学班 |
| H3 | 同一教学班各班次时间不能重叠 |
| H4 | 教室容量 ≥ 教学班人数上限 |
| H5 | 教室类型匹配课程所需类型（实验课→机房、体育课→操场） |

> H5 已实现：`Course.requiredRoomType`（`Any`/`Norm`/`Lab`/`PlayGround`），与 `Classroom.type` 匹配。

---

## 5. 时间离散度规则

一周 N 次课，两次课之间优先间隔 `(5 − N) / (N − 1)` 天（空闲日数）：

| 每周课次 N | 理想间隔 | 示例 |
|-----------|---------|------|
| 3 | 1 天 | 周一/三/五 |
| 2 | 3 天 | 周一/五 |
| 4 | 0 天 | 基本连续上课 |

**放宽机制**：按理想间隔找不到空闲时间时，逐步缩小间隔（如一周 2 次：3 天 → 2 天 → 1 天），直到能排下。

---

## 6. 兜底拆分（同一课程放不进同一时间槽时）

不逐教学班乱排，而是把该课程的教学班按 **`classId` 顺序**拆成若干组，**每组沿用同一套时间模式**。

例：一周 2 次的课程拆成两组 → 一组排周一+周四，另一组排周二+周五。

---

## 7. 教室分配

- **同班同教室**：同一教学班每次课固定在同一教室；
- **best-fit**：选「容量 ≥ 人数且最小」的空闲教室；
- 同时校验容量（H4）与教室类型（H5）。

---

## 8. 复杂度

`O(课程 × 教学班 × 时间槽 × 教室)`。教室按容量预排序，时间槽按周 × 节次扫描。

---

[策略实现](../../src/core/schedule/strategy.cpp) 的 `GreedyStrategy` 已于 **v2.0 对齐本文档**：以课程为单位按「周次数 ↓、单次学时 ↓、教师 ID ↑」排序，每课生成离散度时间模式（间隔 `(5-N)/(N-1)` 天、逐步放宽），同课程教学班共用模式、按 `classId` 兜底拆分，同一教学班固定同一教室（best-fit），并按 `Course.requiredRoomType` 匹配教室类型（H5）。覆盖测试见 `tests/tst_scheduler.cpp`（同课同天 / 同班同教室 / 每周 2 次落周一·周五 / 教室类型匹配）。

## 10. 局限

- **无回退**：排定后不调整，可能陷入局部次优；
- **软约束靠排序顺序保证**：无法全局权衡（如"牺牲一点离散度换更少拆分"）；
- **硬约束排不下时只报告失败**：不尝试修复；失败会附上原因（容量不足 / 类型不符 / 时间冲突），并随工作区快照 `[ScheduleErrors]` 段持久化，供用户对照修改课程。

这些局限由模拟退火弥补（[simulated-annealing.md](simulated-annealing.md) §5 邻域搜索 + §3 软罚分全局权衡）。
