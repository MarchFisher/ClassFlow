# ClassFlow 排课算法策略：模拟退火（Simulated Annealing）

> 版本：v1.1 · 日期：2026-08-27
> 关联：docs/需求分析.md（约束与策略源头）、docs/architecture.md（架构与贪心策略）

---

## 1. 概述

排课问题（University Course Timetabling）本质上是组合优化问题（NP-hard）：要在巨大搜索空间中为一组教学班找到"时间 + 教室"的分配，同时满足多种约束。

本项目采用**两阶段策略**：

1. **构造阶段（Constructive）**：用贪心方法生成一个满足全部硬约束的**可行初始解**（沿用现有 `GreedyStrategy` 的思路）。
2. **优化阶段（Local Search）**：用**模拟退火（Simulated Annealing, SA）**在可行解邻域内反复微调，逐步降低软约束罚分，并通过概率接受劣解跳出局部最优。

这套设计的合理性：排课系统的目标不是"理论最优"（NP-hard 下不可行），而是"**够好且快**"。局部搜索正是工业界排课（ITC 2007 等 benchmark）的主流方案。

---

## 2. 解的表达（编码）

以**课程**为决策单位，一套解由两部分构成：

- **课程时间模式表**：每个课程 → 一组时间槽 `{ (day, startSection) × N }`（N = 该课程每周课次；每个时间槽实际占用**连续 `duration` 个节次**，见下）。同一课程的所有教学班**默认共用**这组时间槽，只靠教室区分。
- **教学班教室分配表**：每个教学班 → 各次课所用的教室。

> 这种编码天然满足需求分析中的「以课程为单位、同一课程所有教学班同一时间模式」。所谓"拆分"（见 §5），只是把某课程的**少数派教学班**移出默认时间模式、另用一组时间槽。
>
> **时间槽是"块"而非单节**：`duration = hoursPerSession` 由学时换算（仅支持整数学时，非整数在数据校验时拒绝）。一个时间槽 `(day, startSection)` 在冲突表与负载统计中按 `startSection ~ startSection + duration − 1` 区间展开；邻域 move（§5）移动的是整个块，保证跨节连续性不被破坏。

---

## 3. 约束与目标函数（罚分制）

模拟退火最小化目标函数：`cost = Σ硬约束罚分 + Σ软约束罚分`。

### 3.1 硬约束（违反 → 大罚分 M，M = 10⁶）

| 编号 | 约束 | 罚分 |
|------|------|------|
| H1 | 同一时间同一教师不能安排两个教学班 | M |
| H2 | 同一时间同一教室不能安排两个教学班 | M |
| H3 | 同一教学班各班次时间不能重叠 | M |
| H4 | 教室容量 ≥ 教学班人数上限 | M |
| H5 | 教室类型匹配课程所需类型（实验课→机房、体育课→操场） | M |

> H5 已实现：`Course.requiredRoomType`（`Any`/`Norm`/`Lab`/`PlayGround`），与 `Classroom.type` 匹配。
>
> **实现口径**：硬约束不进入成本函数，而是由邻域操作的「冲突即拒绝」（`ConflictTable::canPlace` 校验 + 回滚）在源头上保证零违反——等价于罚分 `M = ∞`，仅接受满足 H1~H5 的 move。初始解由贪心构造保证可行，故全程不会出现硬冲突解。

### 3.2 软约束（加权罚分，越小越好）

| 编号 | 软约束 | 罚分定义 | 权重 |
|------|--------|----------|------|
| S1 | **课程不拆分**（同一课程尽量保持同一时间模式） | 每课程 `(时间模式组数 − 1) × w_split` | `w_split = 1000` |
| S2 | **时间离散度**（两次课之间尽量隔理想天数） | 每教学班相邻两次课 `Σ|实际间隔 − 理想间隔| × w_disp` | `w_disp = 100` |
| S3 | **同班同教室**（教学班各次课尽量用同一教室） | 每教学班 `(所用教室种类数 − 1) × w_room` | `w_room = 50` |
| S4 | **教室利用率**（容量 − 人数 的浪费尽量小） | `Σ (capacity − plannedSize) × w_waste` | `w_waste = 0.5` |
| S5 | **时间负载均匀**（各时间槽并发负载尽量均衡） | `Σ_t (load(t) − μ_time)² × w_time` | `w_time = 60` |
| S6 | **教室负载均匀**（各教室占用节数尽量均衡） | `Σ_r (usage(r) − μ_room)² × w_roomload` | `w_roomload = 40` |
| S7 | **避免周末上课**（周末尽量不排课） | 每教学班周末（周六/日）课次数 × w_weekend | `w_weekend = 1000` |

其中 S2 的理想间隔定义为**空闲日数**：`理想间隔 = (5 − N) / (N − 1)`（上课日为周一~周五，共 5 天）。例如：

- N = 3 → 理想间隔 1 天 → 周一/三/五；
- N = 2 → 理想间隔 3 天 → 周一/五；
- N = 4 → 理想间隔 0 天 → 基本连续上课。

**设计说明**：需求分析里"优先理想间隔、找不到再放宽（3→2→1 天）""优先同时间槽、放不下再拆"这类"先满足理想、做不到就退让"的规则，在模拟退火中统一表达为**软罚分**——满足理想 → 罚分为 0；做不到 → 罚分升高但仍可接受，由 SA 在全局权衡是否值得。这比硬性规则更灵活，也更能体现"尽量"的含义。

> **实现口径（×2 整数化 + 7 天网格）**：为消除 `w_waste = 0.5` 的小数与 S5/S6 平方差的小数、保证十万级 move 的位精确可复现，实现内部把全部权重 **×2 取整**：`w_split=2000, w_disp=200, w_room=100, w_waste=1, w_time=120, w_roomload=80, w_weekend=2000`（上表为名义值，二者只是缩放关系，最优解不变）。S5 负载网格取 **7 天 × 最大节次**（含周末，对齐 UI 课表 7 列）；S2 离散度仍按周一~周五计算，两者相互独立。`fullSoftCost` 全量成本含方差 μ 的小数用 `double` 表示；**move 增量 Δ 则完全整数**（见 §5），无浮点漂移。

**S5/S6 的均匀性度量**：两者都回答"整个课表够不够均匀"，以负载的**方差**为罚分——完全均匀时每槽/每教室负载相同、罚分为 0，越偏科越高。方差对全部槽位/教室敏感、梯度平滑，比 `max − min` 更适合 Metropolis 接受概率下的渐进寻优。

- **S5 时间负载**：`load(t)` 为时间槽 `t = (day, section)` 上并发上课的教学班个数（该槽在某周快照下被多少条排课覆盖）；`μ_time` 为其平均值，`T = 7（天）× 最大节次`。S5 促使课程**跨星期、跨节次摊开**，避免出现"周一塞满、周五空转"。
- **S6 教室负载**：`usage(r)` 为教室 `r` 在某周内被占用的节数总和（= 占用该教室各条目的 `duration` 之和）；`μ_room` 为其平均值，`R = 教室总数`。S6 促使各教室**占用节数尽量接近**，避免"几间教室忙不过来、其余闲置"。

> 说明：负载统计以**某周为快照**（周范围不覆盖该周的课不计入）。不同周范围的课程错峰使用同一教室不算冲突，也不会让该周负载失衡；成本计算可抽样少数代表周或按周范围加权，避免全周展开的额外开销。S5/S6 的 `Δcost` 只涉及被移动教学班覆盖的时间槽 / 进出的教室，仍可**局部增量**计算（见 §5）。

## 4. 初始解（贪心构造）

沿用现有 `GreedyStrategy` 的构造逻辑，保证初始解满足全部硬约束：

1. **课程排序**：按「每周课次 ↓、单次学时 ↓、教师 ID ↑」排序（需求分析 §策略 ②），课次多的先排、约束紧的先排。
2. **生成时间模式**：按理想间隔 `(5 − N)/(N − 1)` 生成；按理想间隔找不到空闲时间槽时，**逐步放宽间隔**（3 天 → 2 天 → 1 天）。
3. **同课程同模式**：同一课程的所有教学班放入同一时间模式；若同时刻空闲教室不足，**按 `classId` 拆成若干组**，每组沿用同一套时间模式，不逐教学班乱排（需求分析 §策略 ④）。
4. **教室分配**：选「容量 ≥ 人数且最小」的 best-fit 教室（需求分析 §策略 ⑤），并校验教室类型 H5。
5. 硬约束全程由 `ConflictTable`（`canPlace` / `place`）校验。

> 若贪心也无法生成完全满足硬约束的解，SA 仍可从带硬冲突的解启动，依靠 §3.1 的 M 罚分驱动修复（见 §5 邻域设计）。

> **均匀性起点**：贪心按"先难后易"把课程塞进最靠前的空档，初始解通常**时间与教室负载都很不均匀**（例如大量课程挤在同一两天、同一批教室）。S5/S6 主要由优化阶段负责平滑；权重应保持 S5/S6 的罚分与 S2 离散度同量级，让 SA 有动力把负载摊开。

## 5. 邻域操作（Move）

每次迭代随机从以下 moves 中选一个执行：

| Move | 操作 | 主要影响 |
|------|------|----------|
| **M1 单课平移** | 随机选一个教学班的某一次课，换到另一个 `(day, section)` | 探索时间空间 |
| **M2 整班平移** | 随机选一个教学班，其全部 N 次课一起换到一组新时间槽（保持相对间隔） | 探索时间模式 |
| **M3 课程归并** | 随机选一个被拆分的课程，把其少数派教学班移回多数派时间模式 | 降低 S1 拆分罚分 |
| **M4 换教室** | 随机选一个教学班，换一个满足容量/类型（H4/H5）的教室 | 优化 S3/S4/S6 |
| **M5 双班教室对调** | 随机选两个教学班，交换彼此的教室（双方教室须满足对方的容量/类型 H4/H5） | 优化 S6，不动时间，免去找空位 |

每个 move 产生新解后计算 `Δcost = cost(新) − cost(旧)`：

- `Δcost < 0` → 接受；
- `Δcost ≥ 0` → 以 Metropolis 概率 `exp(−Δcost / T)` 接受。

**实现提示**：`Δcost` 只涉及被移动的教学班及其同课程，应做**局部增量计算**，避免全量重算 `O(教学班 × 时间槽 × 教室)`。S5 的 Δ 只涉及旧/新时间槽（各 `duration` 个）上的负载变化；S6 的 Δ 只涉及旧/新教室的占用变化，同样可局部计算。

> **μ 不变式（S5/S6 Δ 精确整数化）**：任何 move 不改变 session 总数、duration、课程周范围 → 代表周内 S5 总 load 与 S6 总 usage 恒定 → `μ_time` / `μ_room` 不变。因此 S5/S6 的 Δ 恰等于 `w × Δ(Σx²)`，而 `Σx²` 由 `addOccupancy` / `subOccupancy` 增量维护（load `v→v+1` 贡献 `2v+1`，usage `u→u+d` 贡献 `2ud+d²`），**精确整数、无浮点**，只涉及被移动的槽位 / 教室。
>
> **多条目 move 的落子顺序**：整班平移（M2/M3）、双班对调（M5）涉及多条新条目，必须**逐条 `canPlace → place`**（落一个查一个），不可先查全部再落——否则新条目彼此冲突检测不到。失败回滚 = 移除已落新条目 + 恢复全部旧条目（旧条目移动前可行，无需再校验）。
>
> **课次数守恒（M2/M3）**：整班平移的目标天数必须等于该班 `sessionsPerWeek`。M1 可能把某班两次课压到同一天（去重签名天数减少，如「1,4」→「1」），若 M3 拿这种天数不足的签名当目标，会只生成 `targetDays.size()` 个会话导致**丢课次**；`moveClassToDays` 已加校验拒绝天数不足的目标，保证每班课次数全程不变。

## 6. 退火过程（Annealing Schedule）

- **温度调度**：几何降温 `T_{k+1} = α · T_k`，实现取 `α = 0.98`。
- **初始温度 T₀**：只对**通过 `canPlace` 的可行 move** 采样，取 `|Δcost|` 的**中位数 ×5**，并 **clamp 到 [5, 2000]**——避免被少数大 Δ（如拆分 2000）拉爆温度导致高温失控。
- **马尔可夫链长度 L**：`L = 10 × 教学班数`（下限 1）。
- **终止条件**：温度低于阈值 `T < 0.01`，或**低温区连续无改进**（`maxStallRounds = 30` 轮，仅当 `T < 0.5 × T₀` 后才计数，防高温随机游走误触发），或**总 move 数达到上限**（`maxMoves = 150000`）兜底。
- **最优解记录**：best-so-far 在跑第一个 move 前初始化为贪心初始候选（`bestCost = 其完整成本`），算法结束时返回 **best** 而非当前解——因此**保证返回成本 ≤ 贪心**。
- **随机种子**：`std::mt19937` + 固定 seed（默认 `20260831`），可配置，保证测试可复现。

## 7. 参数表（初始建议值，可调）

| 参数 | 含义 | 初始值 |
|------|------|--------|
| `M` | 硬约束罚分 | 冲突拒绝（等价 `∞`），不进入成本 |
| `w_split` | 课程拆分罚分 | `1000`（内部 `2000`） |
| `w_disp` | 离散度罚分 | `100`（内部 `200`） |
| `w_room` | 同班同教室罚分 | `50`（内部 `100`） |
| `w_waste` | 教室浪费罚分 | `0.5`（内部 `1`） |
| `w_time` | 时间负载均匀罚分 | `60`（内部 `120`） |
| `w_roomload` | 教室负载均匀罚分 | `40`（内部 `80`） |
| `w_weekend` | 周末上课罚分 | `1000`（内部 `2000`） |
| `T₀` | 初始温度 | 可行 move `|Δ|` 中位数 ×5，clamp `[5, 2000]` |
| `α` | 降温系数 | `0.98` |
| `L` | 每温度迭代次数 | `10 × 教学班数` |
| `maxStallRounds` | 低温区停滞轮数上限 | `30`（仅 `T < 0.5×T₀` 后计数） |
| `maxMoves` | 总 move 数上限 | `150000` |
| `seed` | 随机种子 | `20260831`（默认固定） |

> 权重比值得注意：`w_split : w_disp : w_room : w_waste : w_time : w_roomload : w_weekend = 1000 : 100 : 50 : 0.5 : 60 : 40 : 1000`——硬性结构（不拆课、同班同教室）与**避免周末上课**仍是最高优先的软约束；**时间与教室的负载均匀**作为次要软约束与离散度同量级，用户可通过上调 `w_time` / `w_roomload` 强化"尽量均匀"的倾向（代价是离散度或拆分可能略有让步）。

## 8. 与现有代码的衔接

- 新增实现位于 `src/core/schedule/`：
  - `annealingstrategy.h/cpp`：`SimulatedAnnealingStrategy`（参数 + 退火主循环 + best 写回）；
  - `annealingcandidate.h/cpp`：候选解 `Candidate` 核心例程（反建 / 写回 / `commit` / `rollback` / `deltaOf`）；
  - `annealingmoves.cpp`：邻域操作 M1~M5（`Candidate` 成员定义，无独立头文件）；
  - `annealingcost.h/cpp`：软约束成本 S1~S7、负载快照 `LoadSnapshot`、增量 Δ 辅助函数，及测试用自由函数 `softCostOfEntries` / `uniformityOfEntries`。
- 候选解内部维护 classId → 会话（时间块 + 教室），**不直接写回 `DataStore`**，算法结束时把 best 一次性按 `(classId, day, section)` 排序生成 `ScheduleEntry` 写回（可复现）。
- 复用 `ConflictTable`（`canPlace` / `place` / `remove`）做硬约束校验与占用维护；决策/写回循环一律迭代排序后的 `QVector`，禁止迭代 `QHash`/`QSet`（Qt5 QHash 迭代序随机）。
- `Scheduler::schedule` 默认策略改为 `SimulatedAnnealingStrategy`（其 `run` 内部先跑 `GreedyStrategy` 构造初始解）；贪心保留为**初始解生成器**，供对比测试显式传参。
- CMake `CORE_SOURCES` 已登记三对新增文件，版本升至 `3.0`。

## 9. 验证与测试

1. **硬约束零违反**：对 `data/small/classic` 与 `data/large/eighteen` 两套样例数据，断言 H1~H5 均满足。
2. **软约束更优**：同一输入下，SA 总软成本 ≤ 贪心 cost——由 best-so-far 初始化为贪心候选**必然成立**（`tst_annealing` 断言）。
3. **均匀性更优**：时间负载方差与教室负载方差 ≤ 贪心结果。注意 **best-so-far 只保证总成本单调，不保证单项方差单调**，故该断言按固定 seed 的**经验属性**处理，`tst_annealing` 放宽到「不劣于贪心 ×1.2 + 1」。实测（seed 20260831）：小数据集时间方差 53.9→21.7、教室方差 182.6→79.0；大数据集 139.7→16.9、795.5→267.8——SA 相对贪心有**大幅**压匀。
4. **规模健壮性**：large 数据集（18 教学班）能收敛且不破硬约束（debug 实测 ~10s 量级）。
5. **可复现**：同一 seed 两次运行结果（写回条目序列）一致。
6. **失败处理**：教室极端不足时，失败上报（`ScheduleResult::failures`，附失败原因）沿用贪心明细，并随快照 `[ScheduleErrors]` 段持久化，供用户对照修改课程。
7. **多学时回归（W1）**：3 学时 / 2 学时课程经 SA 后 `endSection` 仍正确覆盖连续节次（跨节不破）。
8. **周末罚分（S7）**：单班罚分精确为「周末课次数 × w_weekend」；把周末课挪到工作日，软成本恰降一个 `w_weekend`（其余软约束项不变，差值精确为内部权重 2000）。

## 10. 后续扩展

- **教师 / 教室不可用时间段**：新增硬约束 H6（`(id, day, section)` 禁用集），直接进罚分表。
- **无解归因诊断**：硬约束违反时给出"哪些课程/教学班排不下、违反哪条"的报告。
- **学生选课冲突（范围外）**：选课后同一学生两课时间冲突，可预留为 H7（本系统不含学生角色）。
- **均匀性权重自适应**：S5/S6 的权重可按时段空置率 / 教室峰值动态调整，或在 GUI 暴露"均匀性"调节，让教务员在"密集优先 vs 均匀优先"之间权衡。
