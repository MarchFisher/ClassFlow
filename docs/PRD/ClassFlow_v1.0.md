# ClassFlow 高校自动排课系统 — 产品需求文档（v1.0）

> 版本：v1.0 · 日期：2026-08-27 · 状态：MVP 已实现并验证

---

## 1. 项目背景与目标

高校每学期需要为大量教学班安排「上课时间 + 教室」。人工排课依赖经验、耗时数天，且难以避免**教室冲突、教师撞车、容量不足**等问题，调整一次牵一发动全身。

**ClassFlow 的目标**：用一套桌面工具，把「排课」从人工作坊变成「导入数据 → 一键排课 → 出全校课表」的流水线，在几分钟内完成人工数天的工作，并保证约束不违反。

**本期（v1.0 / MVP）**：打通「数据导入 → 自动排课 → 课表展示」全链路，验证核心价值。

## 2. 产品定位

- **使用对象**：教务管理员（当前单机版，无账号体系）
- **形态**：Windows 桌面应用（Qt Widgets，C++ 编写）
- **数据入口**：标准 CSV 文件（教学班、教室、作息表三份清单）
- **数据出口**：全校课表网格 + 排课结果 CSV

## 3. 已实现功能

### 3.1 数据导入

- 一次导入**教学班、教室、作息表**三份 CSV，自动解析入库
- 教学班文件内嵌课程信息，系统自动识别并**去重生成课程模板**（同一门课多班共享，不重复建档）
- 教室类型自动识别：普通教室 / 机房 / 操场，分别匹配不同课程需求
- 作息表即「第几节 · 起止时间」，决定每天可用的时间槽

### 3.2 自动排课

- **贪心策略**：先排「每周课次多、人数多」的难排教学班，再排易排的
- 为每个教学班的每次课自动分配 **（星期，节次）+ 教室**
- 教室选择 **best-fit**：在空闲教室中选「容量恰好够、最小」的一间，避免大班占小班资源

### 3.3 冲突约束（排课硬性保证）

| 约束 | 说明 |
|------|------|
| 同一教学班各次课 | 时间互不冲突 |
| 同一教室同一时间 | 只能安排一个班 |
| 同一教师同一时间 | 只能上一门课 |
| 教室容量 | 必须 ≥ 教学班预期人数 |

### 3.4 全校课表展示

- **横看周几、竖看第几节**（符合阅读习惯），周一至周日 × 每日节次
- 同一时间格多班上课（不同教室）时，**多行堆叠**显示，课程名 + 教室一目了然
- 无课时间格留空，界面清爽

### 3.5 失败诊断与导出

- 教室不足时，明确提示**哪些教学班排不下**，便于排查数据问题
- 排课结果可导出为 CSV（班级、教师、星期、节次、教室），供后续打印/下发

### 3.6 操作界面

- 左侧**侧边栏**：导入 / 导出；右上角：自动排课；右侧 3/4：课表
- 全流程鼠标完成，无需命令行

## 4. 典型使用流程

```
① 准备三份 CSV（教学班 / 教室 / 作息表）
        ↓
② 点击「导入数据」，选择三份文件
        ↓
③ 点击「自动排课」（秒级完成）
        ↓
④ 查看全校课表，确认无冲突
        ↓
⑤ 导出排课结果 CSV
```

## 5. 验证成果

**示例数据规模**：8 个教学班 · 4 门课程 · 9 间教室（普通/机房/操场）· 每天 8 节

| 指标 | 结果 |
|------|------|
| 排课条数 | 17 条全部成功 |
| 冲突数（教室/班级/教师） | 0 |
| 容量违规 | 0 |
| 自动化测试 | 3 个测试套件全部通过 |

> 测试覆盖：CSV 解析与导出往返、冲突检测 7 项、排课正确性 5 项（无冲突、容量满足、课次精确、失败上报、重复排课不累积）。

## 6. 技术架构概要

```
表现层（Qt Widgets 界面）
   ↓
排课核心（贪心算法 + 冲突检测，纯逻辑、可独立测试）
   ↓
数据层（CSV 导入/导出、内存数据仓库）
   ↓
数据模型（课程 / 教学班 / 教室 / 作息）
```

- 三层严格分离，核心逻辑**不含界面代码**，可用自动化测试独立验证
- 纯 C++17 + Qt6，无第三方依赖

## 7. 局限与后续规划

**当前局限（v1.0）**
- 贪心算法得到的是「可行解」，非全局最优（对排满的高负荷场景可能非最佳）
- 单机版，无账号与角色区分，仅服务管理员排课
- 尚未支持选课、学生名单

**已规划的下一步（v1.1）**
- **工作区持久化**：保存 / Ctrl+S、关闭自动保存、启动自动恢复上次工作区，防止误关丢数据
- 教师个人课表、学生个人课表
- 选课与学生名单
- 更强排课策略（回溯等）
