# ClassFlow 高校自动排课系统 — 产品需求文档（v3.0）

> 版本：v3.0 · 日期：2026-09-01 · 状态：自动排课（贪心+模拟退火）已实现并验证

---

## 1. 项目背景与目标

高校每学期需要为大量教学班安排「上课时间 + 教室」。人工排课依赖经验、耗时数天，且难以避免**教室冲突、教师撞车、容量不足**等问题，调整一次牵一发动全身。

**ClassFlow 的目标**：用一套桌面工具，把「排课」从人工作坊变成「导入数据 → 一键排课 → 出全校课表」的流水线，在几分钟内完成人工数天的工作，并保证约束不违反。

**本期（v3.0）**：排课升级为**贪心 + 模拟退火两阶段**，在满足硬约束的前提下引入软约束罚分体系，进一步优化课表质量；同时具备筛选、主题、快照持久化等课表工作台能力。

**演进路径**
- v1.0（MVP）：贪心自动排课，打通「数据导入 → 排课 → 课表展示」全链路；
- v2.x：筛选、主题系统、课程详情、失败诊断、快照与工作区持久化；
- v3.0（当前）：排课升级两阶段优化 + 软约束体系。

## 2. 产品定位

- **使用对象**：教务管理员（当前单机版，无账号体系）
- **形态**：Windows 桌面应用（Qt Widgets，C++ 编写）
- **数据入口**：标准 CSV 文件（教学班、教室、作息表三份清单）
- **数据出口**：全校课表网格 + 工作区快照 + 排课结果 CSV

## 3. 功能需求

### 3.1 数据导入

- 一次导入**教学班、教室、作息表**三份 CSV，自动解析入库
- 教学班文件内嵌课程信息，系统自动识别并**去重生成课程模板**（同一门课多班共享，不重复建档）
- 教室类型自动识别：普通教室 / 机房 / 操场，分别匹配不同课程需求
- 作息表即「第几节 · 起止时间」，决定每天可用的时间槽
- 周范围（startWeek / endWeek）与所需教室类型随课程字段录入

### 3.2 自动排课（两阶段）

- **① 贪心构造可行初始解**：先排「每周课次多、单次学时多」的难排教学班；同课程教学班共用同一套时间模式（间隔 `(5−N)/(N−1)` 天），教室不足时按 classId 兜底拆分、时间间隔逐步放宽；教室 best-fit（容量 ≥ 人数且最小），并匹配课程所需类型（H5）。
- **② 模拟退火优化**：以贪心解为起点，通过 M1~M5 五种邻域操作（单课平移 / 整班平移 / 课程归并 / 换教室 / 双班对调）反复微调，按 Metropolis 概率接受，best-so-far 保证**返回成本 ≤ 贪心解**。
- **课次守恒**：全程保证每班恰排够 `sessionsPerWeek` 次课（回归测试覆盖，防止邻域操作吞课次）。

### 3.3 约束体系

**硬约束 H1~H5（零违反，冲突即拒绝）**

| 编号 | 约束 | 说明 |
|------|------|------|
| H1 | 同班时间互斥 | 同一教学班各次课时间不冲突 |
| H2 | 同教室同时间唯一 | 同一教室同一时间只能安排一个班 |
| H3 | 同教师同时间唯一 | 同一教师同一时间只能上一门课 |
| H4 | 容量满足 | 教室容量必须 ≥ 教学班预期人数 |
| H5 | 类型匹配 | 教室类型匹配课程所需类型（实验→机房、体育→操场） |

**软约束 S1~S7（加权罚分，越小越好）**

| 编号 | 软约束 | 罚分含义 |
|------|--------|----------|
| S1 | 课程不拆分 | 同一课程尽量保持同一时间模式 |
| S2 | 时间离散度 | 两次课之间尽量隔理想天数 |
| S3 | 同班同教室 | 教学班各次课尽量用同一教室 |
| S4 | 教室利用率 | 容量 − 人数 的浪费尽量小 |
| S5 | 时间负载均匀 | 各时间槽并发上课班数尽量均衡 |
| S6 | 教室负载均匀 | 各教室占用节数尽量均衡 |
| S7 | 避免周末上课 | 周六/日每课次高额罚分，尽量把课排在工作日 |

> 权重实现口径：内部全部 ×2 整数化保证十万级 move 位精确、无浮点漂移；名义值见 [docs/algorithms/simulated-annealing.md](../algorithms/simulated-annealing.md) §7。

### 3.4 全校课表展示

- **横看周几、竖看第几节**（符合阅读习惯），周一至周日 × 每日节次，支持按周切换
- 同一时间格多班上课（不同教室）时，**多行堆叠**显示，课程名 + 教室一目了然
- 多学时课程一次课跨连续多节（节次区间完整渲染，跨节不破）
- 无课时间格留空；课表卡片随**主题系统**着色

### 3.5 筛选、详情与诊断

- **筛选**：按教师 / 教室 / 课程多选过滤课表，快速定位
- **课程详情**：点击课表卡片查看课程信息（每周课次 / 单次学时 / 教师 / 教室等）
- **失败诊断**：排不下时列出失败教学班与归因（无对应类型教室 / 容量不足 / 时间冲突），便于排查数据问题

### 3.6 快照、导出与界面

- **快照导入/导出**：完整工作区（含排课结果）可导出为快照文件并恢复
- **工作区持久化**：记忆文件自动保存/恢复，支持 Ctrl+S 手动保存，防误关丢数据
- **结果导出**：排课结果导出为 CSV（班级、教师、星期、节次、教室）
- **界面**：左侧侧边栏（新建/导入/导出）、顶栏（排课/错误/筛选）、右侧课表；全流程鼠标完成

## 4. 典型使用流程

```
① 准备三份 CSV（教学班 / 教室 / 作息表）
        ↓
② 点击「新建」，选择三份文件（自动排课）
        ↓
③ 查看全校课表，用筛选 / 详情 / 错误诊断核对
        ↓
④ 导出工作区快照存档，或导出排课结果 CSV
```

## 5. 验证成果

**示例数据规模**：11 个教学班 · 6 门课程 · 23 间教室（普通/机房/操场）· 每天 8 节

| 指标 | 结果 |
|------|------|
| 排课条数 | 20 条全部成功（每班恰排够每周课次） |
| 冲突数（教室/班级/教师） | 0 |
| 容量 / 类型违规 | 0 |
| SA 相对贪心 | 总软成本 ≤ 贪心；时间/教室负载方差大幅压匀 |
| 自动化测试 | 6 个测试套件、63 项用例全部通过 |

> 测试覆盖：CSV 解析与导出往返、快照往返、冲突检测、贪心排课正确性（无冲突、容量满足、课次精确、失败上报）、筛选判定、模拟退火（硬约束零违反、成本不劣于贪心、负载均匀性、同种子可复现、**课次数守恒**、多学时跨节、周末罚分）。

## 6. 技术架构概要

```
表现层（Qt Widgets 界面：主窗口 / 导入 / 筛选 / 课表模型 / 主题）
   ↓
排课核心（贪心 + 模拟退火，纯逻辑、可独立测试；硬约束经冲突表拒绝保证零违反）
   ↓
数据层（CSV 导入/导出、工作区快照、内存数据仓库）
   ↓
数据模型（课程 / 教学班 / 教室 / 作息）
```

- 四层严格分离，核心逻辑**不含界面代码**，可用自动化测试独立验证
- 纯 C++17 + Qt6，无第三方依赖

## 7. 局限与后续规划

**当前局限**
- 软约束权重为固定建议值，未在 GUI 暴露调节入口（可直接改代码常量）
- 单机版，无账号与角色区分，仅服务管理员排课
- 尚未支持教师/学生个人课表、选课与学生名单、手动改课与锁定重排

**已规划的下一步**
- GUI 暴露软约束权重调节（均匀性 / 拆分 / 周末罚分的权衡滑块）
- 教师个人课表、学生个人课表
- 手动调整单条排课、锁定部分课程后局部重排
- 选课与学生名单（选课后冲突检测预留）
