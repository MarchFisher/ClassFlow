# ClassFlow 编排功能规划：锁定重排 · 教务手动调整 · 新增课程（plan_v3.4）

> 提案版本：v3.4（规划稿） · 当前版本：v3.3 · 日期：2026-09-03 · 性质：**方案先行**——只描述方向与任务划分，W 范围由人工圈定后再分步实施。
> 背景：PRD v3.0 §7「已规划的下一步」中的三项（手动调整单条排课、锁定部分课程后局部重排、新增课程与教学班），本稿一次性给出统一架构并回答"新增课程后要不要重排、怎么最小重排"。

## 1. 现状体检（读码结论）与目标

### 1.1 现状事实

1. **排课入口永远全量清空重建**：`Scheduler::schedule` 先 `clearScheduleEntries()` 再跑策略（[scheduler.cpp:28-41](src/core/schedule/scheduler.cpp#L28-L41)）；`Candidate::applyToStore` 整体清空重写（[annealingcandidate.cpp:107-124](src/core/schedule/annealingcandidate.cpp#L107-L124)）。**今天"排课"= 推倒重排，无"保留现状"概念。**
2. **引擎天然按"教学班"为最小可动单元**：候选解 = `classId → N 个 Session`；邻域 M1/M2/M4/M5 随机抽一个班动（[annealingmoves.cpp:169](src/core/schedule/annealingmoves.cpp#L169) 等），M3 把课程少数派班并回多数派模式。冲突判定全靠 `ConflictTable`，与"班是新来的还是老班"无关。
3. **DataStore 对课程/教学班只有只读访问**，无增改接口；快照为单文件 CSV 分节（[snapshot.cpp:30-130](src/core/store/snapshot.cpp#L30-L130)），[TeachingClasses] 段复用 `loadCsv`。
4. **排课在后台线程对副本跑，成功后整份换源**（[schedulecontroller.cpp:63-136](src/ui/schedule/schedulecontroller.cpp#L63-L136)），取消保旧表；进度框/禁按钮基建可复用。
5. **点卡片 = 只读详情**（[timetablecontroller.cpp:101-169](src/ui/timetable/timetablecontroller.cpp#L101-L169)），无编辑入口。

### 1.2 已确认的产品口径（2026-09-03 与开发者敲定）

| 决策点 | 口径 |
|---|---|
| 锁定粒度 | **整教学班 + "一键锁整门课"**（同课锁 = 循环锁其下各班）；不做单节冻结 |
| 手动调整对象 | 默认改**当前这张卡**（单次周例行课）；弹窗可选**整班搬** |
| 手动调整交互 | **点卡片 → 详情弹窗内"调整"**；不用拖拽 |
| 新增后默认排法 | **最小排：只排新课**，冻结存量 0 扰动；放不下再询问是否对未锁定班局部重排 |

### 1.3 目标

- **G1**：排课可"部分重排"——锁定指定教学班/课程后，其余班重排，锁定班一像素不动。
- **G2**：教务可手动微调单条排课（时段/教室），硬约束（H1~H5）即时校验，不经整表退火。
- **G3**：可在界面上新增课程/教学班并落库；新增后**最小扰动**地把新课排进现有课表，放不下有升格兜底。
- 非目标：拖拽改课、单节冻结、选课与名单、GUI 暴露软权重。

## 2. 统一引擎设计：movable / 冻结

**设计主旨**：给排课引擎引入 **「可动教学班集合 movable」**，movable 之外 = **冻结**。

> 冻结班的现存排课条目**原样种入冲突表占位**（周范围/教室/时段一字不动）；贪心只排 movable 班；退火只对 movable 班做邻域操作（冻结班条目计入负载快照与软成本，只是永不被选中移动）。

一次排课由集合 `M`（本次允许被移动/新安排的班）描述：

1. 冻结班 `F` = 已有排课条目、且 ∉ M 的班；快照其条目 → 清空可动班旧结果 → 把 F 条目回填 store 与冲突表。
2. 贪心**只排 M**：冲突表已含 F 硬占用 → 新班天然不与任何存量冲突。
3. 退火**只动 M**：M1/M2/M4/M5 随机选班从 movable 列表抽；M3 被并对象必须 ∈ movable。
4. best 写回 = F（原样）+ M 新结果。

**一处实现、三处受益**：

| movable 取值 | 得到的能力 |
|---|---|
| 全部班 | 现全量排课（**老行为零回归**，现测试不改全绿） |
| 全部未锁定班 | **锁定重排** |
| 刚新增的班 | **新增后的最小排** |

## 3. 最小重排思路（回答"新增课程后要不要重排"）

**不需要、也不该整表重排**——那会打乱已手动微调/锁定的课表。新班约束是"落在冲突表空位上"，冲突表天然保证不与任何存量冲突。最小重排机制链：

1. **冻结存量**：现有全部已排班作为冻结背景，条目原样进冲突表。
2. **只排新课**：对新增班走贪心 `placeClassInPattern`（离散度 pattern + best-fit 教室），已占的表让贪心不可能落到存量上 → **排上即 0 扰动**。
3. **可选短退火（仍只作用新班）**：新增"已有课程的新班"（如高数 C104 补进 C101~C103）时，S1"课程同模式"大权重罚分会驱动退火把新班并回兄弟模式（M3 目标班必须是 movable，正好就是它），存量依旧不动，排得也好看。
4. **放不下才升格**：贪心在所有 pattern 下都找不到空位 → 说明"不扰动"不可行 → 询问/进入**局部重排**（movable=全部未锁定），只有用户锁定的班仍不动。与"锁定重排"按钮走到同一引擎，无两套逻辑。

## 4. UI 行为设计（摘要）

- **顶栏/侧栏新增入口**：「新增课程…」「锁定重排…」；点卡片详情内加"手动调整 / 锁定本班"。
- **新增课程**：表单（课程 + 首个教学班；已存在同名课程则询问改为"为已有课程新增教学班"）；提交后默认最小排，结束若有失败 → 询问是否局部重排。
- **锁定重排**：弹窗按课程分组列出全部教学班，逐班勾选 + "锁整课"；确定后调 `ScheduleController::runPartial`（后台、进度、取消保旧表）。
- **手动调整**：详情弹窗内"调整此课…"→ 选 单节（星期/节次/教室）或 整班（本期=整班换教室、时刻不变，见 §6 假设）→ 即时冲突提示 → 确认改库并原地刷新。
- 数据持久化：锁定集随快照新增 `[Locks]` 段；手动改存于排课条目，随 Ctrl+S 记忆文件持久化。

## 6. 产品假设与风险边界

- **假设**："整班搬"实现为**整班换教室、各节时刻不变**；"把 N 节课时刻整体重选"对每周多节不成立、更像引擎职责，不在本期。若口径不同需指出。
- **锁定只对"当前已有排课"的班有意义**：已失败班即使被锁，重排仍会尝试安排（否则变"永不排"），写入提示文案。
- 手动改可打破 S1/S3 软约束——**只校验硬约束 H1~H5**，软约束是用户自由。
- 表排满时最小排必失败 → 内置升格局部重排兜底。
- 排课后台副本/取消保旧表/进度框全部复用 `ScheduleController`，不新建线程基建。
- 全部改动文件保持 <500 行；UI 弹窗统一现有样式 token（与 plan_v4.0 UI 方案不冲突，逻辑与观感解耦）。
