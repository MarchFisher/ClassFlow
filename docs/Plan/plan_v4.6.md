# ClassFlow 保存分层：自动恢复 与 手动保存项目文件（plan_v4.6 · 方案先行）

> 提案版本：v4.6 · 当前版本：v4.0 · 日期：2026-09-05 · 性质：**方案先行**——把现有“保存”拆成自动/手动两层语义，描述目标行为与改动点，W 范围由人工圈定后再分步实施（沿用 v3.5 起编辑功能与 W1..W 惯例）。
>
> 修订记录（2026-09-05 实施后回改）：**侧栏按钮不并入保存体系**——由上一版敲定的「另存为」恢复为独立**「导出快照」**（选路径另存一份副本，**不设为当前项目文件**、不挪 Ctrl+S 落点）；项目文件保存只由顶栏「保存」/ Ctrl+S 承担（首存弹路径）。另：顶栏 保存/撤销/重做 改为 图标+文字（Feather save/rotate-ccw/rotate-cw，含禁用灰态），图标源自本稿后迁根目录 `icons/`（icons.qrc，前缀 /theme/icons）——UI 侧调整，不改变本稿两层保存语义。

## 0. 一句话

现在 **Ctrl+S / 保存按钮** 与 **关闭自动保存** 写的是**同一个隐藏文件** `.classflow/workspace.dat`，手动保存形同虚设；且“导出快照”每次都要重选路径、不跟 Ctrl+S 挂钩。本稿把保存拆成两层——

- **L1 自动恢复层（隐式）**：任何改动后**防抖自动写** `workspace.dat`，关窗再补一次 → 关闭时即使没按过保存，下次启动也能回到现场（VSCode 式“未保存也能找回”）。
- **L2 手动保存层**：Ctrl+S 把工作区写到教务选定的**项目文件**；**首次保存 = 另存为/导出**（弹路径选目标），之后 Ctrl+S 直接覆盖该文件，路径**跨会话记住**。

## 1. 现状与缺口（读码结论）

| 动作 | 现状 | 落盘目标 |
|---|---|---|
| 启动 | 有则恢复上次现场 | `.classflow/workspace.dat` |
| 关闭 / 新建前 | `saveMemory()` 自动写 | 同一个 `workspace.dat` |
| **保存按钮 / Ctrl+S** | `onSaveClicked → saveMemory()`（[mainwindow.cpp:568](src/ui/mainwindow.cpp#L568)） | **同一个 `workspace.dat`** |
| 导出快照 | 每次 `getSaveFileName` 另存（[mainwindow.cpp:553](src/ui/mainwindow.cpp#L553)） | 用户每次自选路径 |
| 导入快照 | 选文件 `loadSnapshot` 恢复 | — |

四条缺口：

1. **手动 = 自动**：Ctrl+S 和关窗写同一隐藏记忆文件，没有“保存到我自己选的文件”的语义；用户侧看 Ctrl+S 没有任何独立作用。
2. **落盘用户文件的入口只有“导出快照”**，且不记目标、不与 Ctrl+S 挂钩——不符合“像其它软件的保存键”的直觉。
3. **无“当前项目文件”概念**：窗口标题恒定 `ClassFlow - 自动排课`（[mainwindow.cpp:69](src/ui/mainwindow.cpp#L69)），无脏标记、无法从标题得知当前存档名。
4. **自动保存只在关窗/新建前触发**：运行中程序崩溃/断电，本次会话改动（编辑、手动调课、排课结果）全部丢失——不是真正的“自动保存”。

## 2. 已确认口径（2026-09-05 与开发者敲定）

1. **自动恢复层**：任意改动后**防抖自动写**（约 1.5s）；关窗再补一次防抖未触发时的 flush。
2. **手动保存 = 首次即导出**：Ctrl+S /「保存」写**项目文件**；尚无目标文件时首次弹窗选路径（= 导出语义），之后 Ctrl+S 直接覆盖。侧栏按钮维持**「导出快照」**为**独立副本**：选路径另存一份当前现场，**不改当前项目文件**、不挪后续 Ctrl+S 落点（修订：见文首）。
3. **路径跨会话记住并沿用**：启动后用标题显示文件名；Ctrl+S 直接覆盖记住的文件。
4. **关窗不弹“是否保存”**：静默走自动恢复（VSCode 行为，不改默认）。
5. **导入快照 ≈ 打开项目文件**：加载成功后把该文件设为当前项目文件（此后 Ctrl+S 指向它）。
6. **快照格式不变**：九段 CSV（*.csv / *.dat），老文件与老版本仍兼容。

## 3. 设计

### 3.1 存储分层模型

```
                        ┌────────────── 运行态内存 DataStore（m_store） ──────────────┐
                        │  唯一数据源：编辑/调课/排课结果都在这里                        │
                        └───────────────▲───────────────────────────▲──────────────┘
              防抖自动写(改动后~1.5s)     │                            │  Ctrl+S / 保存
              关窗/新建/导入前 flush       │ 启动:总是恢复它(最新现场)      │
                                        │                            ▼
              L1 自动恢复  .classflow/workspace.dat   (gitignored)   L2 项目文件(教务自选)
              用户基本感知不到                          首次保存→弹路径(=导出语义),此后覆盖
```

- **L1 `workspace.dat`** = 文档本体/现场恢复。启动总从它恢复 → “没按过 Ctrl+S，关掉再开改动还在”。
- **L2 项目文件** = 教务主动产出的存档副本：可分享、备份、日后经「导入快照」打开。内容只在 Ctrl+S（首次=选路径）时更新，可能比最后一次会话的现场旧（正常，未保存的差异由标题 ● 标出）。侧栏「导出快照」只另存副本、不改此文件身份。

### 3.2 改动检测与防抖自动写（快照文本指纹比对）

任何会改数据的入口都要被“自动写”覆盖（编辑弹窗、手动调课、排课换源、撤销/重做、新建/导入都直接或间接改 `m_store`）。**实现采用快照文本指纹比对（小改动路线，无需逐个方法插计数）**：

- DataStore 新增 `snapshotText()`（[snapshot.cpp](src/core/store/snapshot.cpp)）：把 saveSnapshot 的九段写盘内容先在内存拼成 QString；`[Locks]` 段锁定 id **先排序再写**，保证“同一内容 → 同一文本”逐字节确定。`saveSnapshot` 改为取 `snapshotText()` 后统一落盘，写盘格式不变。
- [mainwindow.cpp](src/ui/mainwindow.cpp) 起一个 ~1.5s 的防抖 `QTimer`：每次把 `m_store.snapshotText()` 与上次自动写记录的文本比对，**不同才** `writeWorkspace()` 写 L1。任何改动都会让文本变化 → 天然覆盖所有入口（含 TimetableController 弹窗内直改 `m_store` 的路径），无需在 UI 各路径手插标记。
- 标题脏标记 ● 同理：以“最近一次手动保存/导入到项目文件的 `snapshotText()`”为基准比对。
- `closeEvent`（[mainwindow.cpp:445](src/ui/mainwindow.cpp#L445)）与「新建/导入前」保留原有 flush（同调 `writeWorkspace()`）；防抖未触发时由它兜底保证最新。

### 3.3 手动保存 与 导出快照（独立副本）

| 入口 | 行为 |
|---|---|
| 顶栏「保存」/ **Ctrl+S** | 已有当前项目文件 → 直接覆盖写；**无 → 首次弹路径选目标**（弹 `getSaveFileName`）。成功状态栏“已保存到 <文件名>”，脏标记熄灭 |
| 侧栏**「导出快照」**（独立副本） | 弹路径选目标 → 只写快照副本，**不设为当前项目文件**（可分发给他人/备份；Ctrl+S 落点不受影响） |
| 导入快照成功 | 把导入文件设为当前项目文件（口径 §2.5） |

- 快照写盘仍用现有 `DataStore::saveSnapshot`（[datastore.h:27](src/core/store/datastore.h#L27)），不改格式。
- 排课期禁用集合：导出快照沿用现 `exportBtn` 位置（排课时禁用）；顶部「保存」/ Ctrl+S 维持现状可点（写的是排课进行中不动的 `m_store` 静态态，安全）。
- 旧 `saveMemory()` 职责收窄为“写 L1”，改名避免与手动保存混淆（如 `writeWorkspace()`）；其调用点（closeEvent/新建前）全部指向 L1。

### 3.4 标题 / 脏标记 / 路径记忆

- **标题**：`ClassFlow · <项目文件基名><●>`；尚无项目文件 → `ClassFlow · 未命名●`（提示该做第一次保存）。有文件且有未保存差异 → 文件名后加 `●`。
- **脏标记（●）判据** = “当前内容 ≠ 最近一次手动保存到项目文件的内容”（尚无项目文件且非空 → 视为脏）。实现用**快照字节比较**：手存/另存/导入时记录“刚写入的序列化字节”，改动检测到 revision 变化时对比一次刷新标题。
- **跨会话记忆**：用 `QSettings`（org/app 名沿用工程）存**最近项目文件路径**；启动读到则标题显示其文件名。文件已被删除/移动 → 视作“无项目文件”，内容保留为「未命名●」，不清空现场（不自动丢用户数据）。
- **启动脏态**：内容来自 L1（可能比记住的项目文件新）。判据按 §3.4 与记住文件的字节比较得出（一致则无 ●，不一致则 ●）。老快照若字节写法有出入最多误显一次 ●，下次 Ctrl+S 即消除——纯显示层，不丢数据。

### 3.5 现有流程迁移对照

| 现有 | 改为 |
|---|---|
| 关窗 `saveMemory()` → workspace.dat | 同目标，改名 `writeWorkspace()` 收尾 flush |
| 新建前自动保存原工作区 | 不变（写 L1） |
| Ctrl+S / 保存 → workspace.dat | 改写**项目文件**；无目标首次弹路径 |
| 导出快照（独立副本） | 维持原义：选路径另存副本，**不**写入当前项目文件身份 |
| 启动：有 workspace.dat 就恢复 | 不变；恢复后按 §3.4 定标题/脏态 |

## 5. 风险与边界

- **文本比对代价**：防抖每 tick 把 DataStore 串行化到内存一次（当前几 KB 文本，代价可忽略）；若未来数据量大增再考虑变更计数/增量方案。
- **锁定集迭代无序**：QSet 顺序不稳定会让同内容的文本抖动（误写 / 误标 ●）→ `[Locks]` 段写前排序（已并入 `snapshotText()`，[tst_snapshot](tests/tst_snapshot.cpp) 的 `snapshotTextStable` 覆盖反序插入一致）。
- **脏标记基准读回再序列化**：启动对记住的项目文件先 `loadSnapshot` 再 `snapshotText()` 求基准，天然兼容老快照格式（内容等价即不标 ●），避免字节差异误标；即便误标也纯显示层、一次 Ctrl+S 消除。
- 同步写盘文件很小，1.5s 间隔不阻塞 UI；暂不做后台线程写与增量。
- 排课期间 `m_store` 是静态的，Ctrl+S/自动写都安全；「导出快照」沿用现 exportBtn 禁用位（现出口即文件写盘，禁用避免与换源竞态）。

## 6. 验收（P0）

1. **自动恢复**：做任意改动后**不按 Ctrl+S** 直接关窗，重开 → 改动还在；运行中崩溃/结束进程，重开同样在（W2 相对现状的增量）。
2. **首次保存 = 导出**：新建工作区 → Ctrl+S 弹路径 → 生成文件；状态栏提示保存到文件名。
3. **覆盖保存**：再改几处 → Ctrl+S **不弹窗**直接覆盖同文件；标题 ● 灭。
4. **脏标记**：保存后再改 → 标题出现 ●；未保存即关窗重启 → 内容仍在且 ● 仍显示（提示相对记住文件有差异）。
5. **导出快照独立副本**：导出到某路径 → 当前项目文件身份/标题 ● 不变，之后 Ctrl+S 仍落原项目文件（副本与 Ctrl+S 互不影响）。
6. **跨会话记忆**：重启后标题显示上次项目文件名，Ctrl+S 直接覆盖。
7. **导入设为当前**：导入某项目文件后 Ctrl+S 覆盖该文件本身。
8. `ctest` 9/9 无回归；改动各文件 <500 行。
